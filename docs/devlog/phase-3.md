### 2026-10-02 · P3-13 · [booking-tools] [voice] · Short identifiers: `offer_id` and the eleven-character read-back code (D-059)
- **Goal:** a speech model must be able to carry what one tool returns into the next call. The developer chose option A after the finding of the previous entry.
- **Experiment first (stub MCP server, real Nova 2 Sonic, 3 conversations):** an 8-character offer id, a 32-character hold id and an 11-character read-back code were copied correctly every time, and all three conversations booked.
- **Done:** `server/domain/offers.py` (alphabet, `SlotClaims`, reading of a code that a model wrote with capitals, dashes or look-alike letters), `server/offers.py` (`OfferBook`: `availability_check` stores up to five offers in one transaction with `attribute_not_exists`, `reservation_hold` reads one, checks the user and the expiry), `ReadBackCodec` rewritten as 3 characters of time (half seconds, rounded up) plus 8 characters of HMAC, nothing stored; `slot_token` became `offer_id` everywhere (about 135 places in code, tests and READMEs), error codes `INVALID_OFFER` and `OFFER_EXPIRED`, `OFFER_TTL_S`, the DynamoDB table gets `ttl` switched on in CDK, invariant I1 allows one second, `old server/domain/slot_token.py` and its test deleted.
- **Found while testing with the model:** (1) the model reuses short idempotency keys such as `hold-luna-1` in every conversation, so a new conversation was handed the stored result of an old hold that had been cancelled and reported a booking that was not there; a repeat of an agent's hold is now replayed only while that hold is live, otherwise it is an `IDEMPOTENCY_CONFLICT` and the model is told to use a new key (`replay_is_stale`, `server/pipeline.py`). (2) The model asked the availability tool for the whole evening and, with only five slots shown, held 6:00 PM for a request for 7:00 PM; the tool description and the voice prompt now say to give just the time that was asked. (3) One sentence added to the voice prompt ("copy the read_back_token exactly, character for character") made Bedrock refuse the whole session with "This request has been blocked by our content filters"; it was taken out. (4) Once the model sent an invented value that looked like a base64 JSON string as `read_back_token`; it recovered on the second try.
- **Tests:** the whole local suite after the last change: 1106 passed, 42 skipped, 5 failed: the five CDK synthesis tests, which ran while a `cdk deploy` and a package build used the same folders; run alone they pass (49 of 49). `ruff` clean. Earlier in the day unit 746 passed; new `tests/unit/domain/test_offer_codes.py`, `tests/integration/test_offers.py` (7), a stale-replay test; real AWS: the whole `tests/aws` passed (37) and the spoken booking passed on four runs in a row with different diners (right time, offer copied right, asked once, booked after one yes).
